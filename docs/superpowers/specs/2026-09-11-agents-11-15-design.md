# Agents 11-15 and orchestrator integration — design

Date: 2026-09-11. Approved in chat before implementation.

## Scope

Build agents 11-15 from `New Text Document.txt` as `BaseAgent` subclasses
registered in `REGISTRY` (so they get a form page for free), and wire the
per-case ones into the LangGraph Exit Process Orchestrator.

| # | Agent | In orchestrator? | Why |
|---|-------|------------------|-----|
| 11 | Multi-System Clearance (tool use) | Yes, parallel branch | Per-case; its status is evidence for compliance |
| 12 | Document Collection (OCR validation) | Yes, parallel branch | Per-case; missing docs are evidence for compliance |
| 13 | Exit Workflow Optimizer | No | Analyzes all historical cases, not one case |
| 14 | Automated IT Deprovisioning (HITL) | Yes, plan in parallel row, then approval gate + execute | Per-case; access revocation is what compliance checks |
| 15 | Exit Interview Trend Analyst (multi-turn) | No | Longitudinal over all interviews, not one case |

## New graph

```
START -> load_case
  -> checklist | risk_assessment | routing | clearance | documents | deprov_plan   (parallel)
  -> approval_gate   (LangGraph interrupt(); run pauses until a human resumes)
  -> deprov_execute  (approved) | skipped (rejected)
  -> compliance -> END (cleared) | escalate -> compliance ... (unchanged, MAX_RETRIES=2)
```

- Graph compiled with `MemorySaver` checkpointer; each run gets a `thread_id`
  (the SSE stream returns it in `run_start`).
- `approval_gate` calls `interrupt({"plan": ...})`. The stream yields
  `awaiting_approval {thread_id, plan}` and stops. `POST
  /api/orchestrate/{case_id}/resume` with `{thread_id, decision: approve|reject,
  note}` resumes via `Command(resume=...)` and streams the rest of the run.
- `compliance` gets extra evidence: consolidated system status (11), document
  status (12), deprovisioning execution log or "not performed" (14).

## Agent designs

### 11 Multi-System Clearance Agent — `backend/agents/multi_system_clearance.py`
- Real tool calling: `llm.complete_with_tools(system, user, tools, handlers)`
  loops on `finish_reason == "tool_use"` until the model answers (max 8 rounds).
  Verified 2026-09-11 that Portkey -> Bedrock Sonnet 5 returns
  `tool_calls` for OpenAI-style `tools`.
- Tools are mock connectors in `backend/systems.py` (IT asset management,
  HRMS, finance), deterministic, derived from the employee + case records so
  they agree with the rest of the data.
- Output: `{systems: [{system, status: clear|blocked|pending, items:[...]}],
  overall: clear|blocked, tool_trace: [{tool, args, result_summary}], summary}`.
- Input: `case_id`.

### 12 Document Collection Agent — `backend/agents/document_collection.py`
- Required documents per stage come from `data/process-docs/documents-required.md`
  (parsed in code by heading). Submitted documents come from a new
  `documents:` list in each exit case's frontmatter (added to sample data).
- Output: required vs submitted vs missing per stage, drafted reminder emails
  for missing ones (LLM), and any validation results.
- Upload validation: new `Field(type="file")` rendered as `<input type=file>`;
  generic `POST /api/agents/{id}/upload` (multipart) runs **local OCR** then one
  short text LLM call judges whether the OCR text matches the expected document
  (title, employee name, signature/date cues). Chosen over Claude vision for
  latency and so the image never leaves the machine.
  - Engine decision (measured 2026-09-11 on this machine): `rapidocr` (PP-OCR on
    ONNX Runtime) read the sample form perfectly but took 6-10 s/page here;
    Windows' built-in OCR via `winocr` read it identically in ~0.4 s. So:
    `winocr` first on Windows, `rapidocr` as the portable fallback.
- Input: `case_id`, optional upload + `document_name`.

### 13 Exit Workflow Optimizer — `backend/agents/workflow_optimizer.py`
- Code computes: per-stage avg/max days, per-department delays, owner load,
  overdue rate, stage ordering dependencies observed in timeline notes.
- LLM proposes reconfigurations: parallelize stages, reassign owners, SLA
  changes, with expected gain and risk. No inputs.

### 14 Automated IT Deprovisioning — `backend/agents/it_deprovisioning.py`
- `plan(employee)`: LLM builds an ordered plan from `access_systems`,
  `assets_assigned`, exit type, and the IT deprovisioning policy:
  `{accounts_to_disable, access_to_revoke, data_to_archive, credential_rotations,
  sequencing, requires_approval: true}`.
- `execute(plan)`: mock connectors in `backend/systems.py` "perform" each
  action and return timestamps; deterministic, no LLM.
- Standalone page: run -> plan + Approve button -> `POST
  /api/agents/it_deprovisioning/execute` -> execution log.
- Orchestrator: plan node in the parallel row; `approval_gate` interrupt;
  `deprov_execute` node.

### 15 Exit Interview Trend Analyst — `backend/agents/interview_trends.py`
- Chat UI (reuses `renderChat` with an auto first turn). Code groups
  interviews by department and quarter, tallies themes/sentiment from
  frontmatter, and computes deltas. First turn: LLM writes the longitudinal
  analysis and emits `alerts`. Follow-ups: `question` + `history`.
- Output: `{answer (markdown), alerts: [{department, signal, severity}], sources}`.

## Frontend
- Diagram: widen viewBox, six parallel circles, approval-gate diamond-ish
  node, execute node; `awaiting_approval` shows an approval panel under the
  diagram with plan summary + Approve / Reject; resumes via the resume route
  and re-attaches to the SSE stream.
- Result sections: System clearance, Documents, Deprovisioning plan,
  Approval decision, Execution log.
- `renderField` supports `file`; agent 15 routes to chat like `faq_chatbot`.

## Testing
- Mocked-agent graph test: pause at gate, resume approve, resume reject.
- Live: each agent once; one live orchestration on `case-001` with approve.
