# Knowledge Transfer — Dev Patel (Cloud Infrastructure & CI/CD)

## System Overview
The AWS environment is a multi-account landing zone managed with Terraform
(state in an S3 backend with DynamoDB locking). Accounts: `mgmt`, `shared`,
`prod`, `staging`, `dev`. Networking uses a Transit Gateway hub.

## Terraform / IaC Notes
- Root module lives in the `infra-live` repo; modules in `infra-modules`.
- `terraform plan` must be run against the `prod` workspace with the
  `prod-deployer` role. Never apply from a laptop; use the pipeline.
- State is locked per-workspace; a stuck lock can be released via the DynamoDB
  `terraform-locks` table.

## CI/CD Platform
- GitHub Actions with self-hosted runners in the `shared` account.
- Deployment pipelines gate on the `staging` smoke tests before `prod`.

## Deployment / Runbook
- To deploy infra: open PR to `infra-live`, pipeline runs plan, requires one
  approval, then apply on merge.
- Rollback: revert the merge commit; the pipeline re-applies the previous state.
- Incident runbook: check CloudWatch dashboard `platform-overview`, then
  PagerDuty for the triggering alarm.
