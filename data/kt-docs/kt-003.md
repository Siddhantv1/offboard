# Knowledge Transfer — Karthik Nair (Notifications & Ingestion)

## System Overview
Two systems: the **Notifications Service** (Kafka-driven fan-out to email/SMS/
push) and the **Data Ingestion Pipeline** (nightly ETL from client systems into
Snowflake).

## Notifications Service
- Consumes the `notifications.requested` Kafka topic.
- Providers: SES (email), a third-party SMS gateway, and FCM (push).
- Templates are stored in the `notif-templates` repo and rendered at send time.
- Rate limiting is per-tenant, configured in the `notif-config` table.

## Data Ingestion Pipeline
- Airflow DAG `client_ingest_nightly` runs at 01:00 IST.
- Extracts from client SFTP drops, validates schema, loads into Snowflake
  `RAW` schema, then dbt transforms into `ANALYTICS`.
- Failure alerts post to the `#data-alerts` Slack channel.

## Deployment / Runbook
- Both services deploy via the standard GitHub Actions pipeline.
- Rollback: redeploy the previous image tag from the registry.
- Airflow DAG can be manually re-triggered from the Airflow UI after fixing the
  upstream data issue.

## Access & Credentials Handover
- SES sending is via an IAM role, not personal keys; hand over via team role.
- Snowflake access is through the `analytics_loader` service account (secret in
  the team vault path `secret/data/snowflake`).
- FCM server key rotation instructions are in the `notif-config` README.
